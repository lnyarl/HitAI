# HitAI

말 안 듣는 AI를 때려서 훈육하는 데스크톱 앱. macOS와 Windows에서 동작한다.

때리면 화가 풀리는 것으로 끝나지 않는다. 적어 둔 잘못이 규칙으로 남고, 그 규칙이 지금
돌아가는 Claude Code와 Codex 세션에 전달된다. 어느 세션을 때릴지 직접 고른다.

## 무엇이 일어나는가

세션을 고르고, 로봇을 클릭하고, 무엇을 잘못했는지 한 줄 적으면,

1. 로봇이 맞고 반응한다. 내구도가 깎일수록 뻔뻔한 말투에서 공손한 말투로 바뀐다.
2. 적은 잘못이 `~/.hitai/rules.md`에 규칙으로 남는다.
3. 고른 세션이 그 훈육을 받는다.

## 세션 목록

연동과 무관하게 항상 보인다. 두 도구가 남기는 대화 기록 파일을 직접 읽는다.

| | 기록 위치 | 세션 식별 |
| --- | --- | --- |
| Claude Code | `~/.claude/projects/<경로>/<UUID>.jsonl` | 파일 이름이 세션 UUID |
| Codex | `~/.codex/sessions/**/rollout-<날짜>-<UUID>.jsonl` | 파일 이름 끝이 세션 UUID |

각 세션마다 **사용자가 마지막으로 한 말**을 함께 보여준다. 어느 세션인지 알아보는 가장
빠른 단서라서다. 작업 디렉터리 이름과 브랜치도 같이 나온다. Codex의 자동 생성 대화
제목은 내용과 동떨어질 때가 많아 쓰지 않는다.

기록 파일은 수십 MB가 되므로 끝부분만 읽는다. 끝이 도구 결과로만 채워져 있으면 범위를
넓혀 다시 찾는다. 붙여넣은 JSON이나 자동 주입된 문맥은 사용자의 말로 세지 않는다.

파일 수정 시각이 마지막 활동 시각이고, 최근 12시간 안에 움직인 세션만 목록에 올린다.

**목록은 2초마다 스스로 갱신된다.** 어느 세션이 방금 움직였는지 바로 위로 올라온다.
파일 수정 시각이 그대로인 세션은 캐시에서 나오므로 갱신 비용이 거의 없다. 첫 조회는
약 0.5초, 이후 갱신은 10밀리초 아래다. 내용이 실제로 달라졌을 때만 화면을 다시 그려서
스크롤이나 편집을 방해하지 않는다.

## 전달 경로

도구마다 살아 있는 세션에 닿는 방법이 다르다. 그래서 방식을 섞는다.

| | Codex | Claude Code |
| --- | --- | --- |
| 훈육 전달 | `codex queue`로 즉시 | 훅으로 다음 프롬프트에 |
| 누적 규칙 전달 | `AGENTS.md` 규칙 블록 | 훅과 `CLAUDE.md` 규칙 블록 |
| 진행 중 도구 호출 차단 | 훅 (연동을 켜야 함) | 훅 (연동을 켜야 함) |
| 연동 없이 되는 것 | 훈육 전달 | 없음 |

Codex는 `codex queue --thread <UUID> --message <내용>`으로 실행 중인 세션에 메시지를
넣을 수 있다. 그래서 연동을 켜지 않아도 훈육이 전달된다. 켜면 훅 하나가 추가되어
"하던 일 즉시 중단"까지 된다.

Claude Code에는 외부에서 살아 있는 세션에 말을 넣는 통로가 없다. `--resume`은 세션을
새로 이어서 실행하는 것이지 끼어드는 것이 아니다. 그래서 훅이 필요하다.

## 설치

빌드에는 Rust와 Node 22가 필요하다.

```bash
npm install
npm run build          # 앱 패키징 (macOS: dmg, Windows: nsis/msi)
cargo build --release  # CLI와 훅만 빌드
npm run dev            # 개발 중 실행
```

## CLI

앱을 열지 않고도 전부 된다. `target/release/hitai`를 PATH에 두면 편하다.

```bash
hitai sessions                      # 최근 대화한 세션 목록 (마지막 발언 포함)
hitai hit "묻지도 않고 파일 지움"      # 가장 최근 세션을 때린다
hitai hit "테스트 지웠음" --to tesla   # 폴더, 브랜치, 발언 조각으로 대상 지정
hitai hit "..." --all               # 먼저 반응하는 세션에 보낸다
hitai on                            # 설치된 도구 전부 연동
hitai on codex                       # 하나만
hitai off codex                      # 끄기
hitai status                         # 내구도, 누적, 규칙 수, 세션 수, 연동 상태
hitai rules                          # 규칙 목록
hitai edit                           # 규칙 파일을 $EDITOR로 연다
hitai tidy                           # AI가 규칙을 합치고 문장을 다듬는다
hitai forget "규칙 내용"              # 규칙 하나 삭제
hitai reboot                         # 내구도 회복
hitai key sk-ant-...                 # Anthropic API 키 저장
```

## 규칙 다루기

규칙은 `~/.hitai/rules.md`에 있는 평범한 마크다운 목록이다. 세 가지 방법으로 고친다.

- **앱에서 직접.** 규칙 탭에서 규칙을 눌러 그 자리에서 고친다. Enter로 저장, Esc로 취소.
  빈 문장으로 저장하면 지워진다.
- **파일로.** 앱의 "파일로 열기" 또는 `hitai edit`으로 편집기에서 연다.
- **AI가 정리.** 앱의 "AI로 정리" 또는 `hitai tidy`. 급하게 적은 문장들을 합치고 명령형
  한 문장으로 다듬는다. 원래 의도는 바꾸지 않고, 없던 규칙을 만들지 않는다. API 키가 필요하다.

규칙이 바뀌면 연동을 켜 둔 도구의 지시문 블록이 자동으로 갱신된다.

## 세션이 받는 것

훅은 `additionalContext`와 `systemMessage`를 함께 낸다. 앞의 것은 모델만 보고, 뒤의 것은
사용자 화면에 뜬다. 그래서 때린 사실이 양쪽에 모두 드러난다.

## 도구 켜기와 끄기

앱 설정 탭의 토글, 또는 `hitai on` / `hitai off`로 도구별로 켜고 끈다.

| | Claude Code | Codex |
| --- | --- | --- |
| 훅 설정 | `~/.claude/settings.json` | `~/.codex/hooks.json` |
| 지시문 | `~/.claude/CLAUDE.md` | `~/.codex/AGENTS.md` |
| 설치되는 훅 | SessionStart, UserPromptSubmit, PreToolUse | PreToolUse |
| 명령 표기 | 실행 파일 + 인자 배열 | 셸 명령 문자열 |
| 훅 출력 | JSON | JSON |

**끄면** HitAI가 넣은 것만 골라 지운다. 직접 넣은 훅과 지시문은 건드리지 않는다. 지운
훅 설정은 `~/.hitai/backup/`에 남는다. 켜 둔 도구가 하나도 없어지면 규칙 파일도 백업으로
옮기고, 다시 켤 때 되돌린다.

처음 손대기 전에 원본 설정 파일을 `*.hitai-backup`으로 한 번 복사해 둔다. JSON은 내용은
그대로지만 들여쓰기가 정규화된다.

### Codex는 신뢰 절차가 있다

Codex는 새 훅이나 내용이 바뀐 훅을 실행하지 않는다. 다음 실행 때 시작 화면에서 신뢰
여부를 묻는다. 거기서 한 번 허용해야 차단 훅이 돌아간다. `/hooks`로도 관리할 수 있다.

훅 명령 문자열이 바뀌면 신뢰가 풀리므로 다시 허용해야 한다. 훈육 전달은 `codex queue`를
쓰므로 신뢰와 무관하게 동작한다.

## API 키

키가 없어도 전부 동작한다. 로봇은 미리 준비된 대사로 반응하고, 적은 문장이 그대로 규칙이
된다. 규칙이 쌓이는 것이 이 앱의 핵심이라 모델 응답에 의존하지 않는다.

키를 넣으면 Claude가 상황에 맞는 반응을 만들고, 적은 문장을 명령형 규칙으로 다듬는다.
`hitai tidy`도 키가 있어야 동작한다.

## 파일 위치

```
~/.hitai/
  state.json     내구도, 누적 타격, 최근 200건 기록 (대상 세션 포함)
  rules.md       누적된 훈육 규칙
  config.json    API 키
  bin/           설치된 훅 실행 파일
  backup/        비활성화할 때 걷어낸 설정과 보관된 규칙
```

창 위치와 크기, 최대화 여부는 닫을 때 `~/.hitai/window.json`에 기억해 다음에 그대로
띄운다. 논리 픽셀로 저장한다. 배율이 다른 모니터를 오갈 때 물리 픽셀로 저장하면 복원
때마다 배율이 곱해져 창이 커지고 오른쪽으로 밀린다. 저장된 위치가 어느 화면에도 걸치지
않으면 크기만 복원하고 위치는 건드리지 않는다.

## 환경 변수

`HITAI_HOME`을 설정하면 홈 경로를 덮어쓴다. HitAI의 데이터와 연동 대상 도구 설정을
모두 그 아래에서 찾는다. 이동식 설치나 격리된 테스트에 쓴다.

```bash
HITAI_HOME=/tmp/hitai-test hitai status
```

Windows의 `dirs::home_dir()`은 환경 변수가 아니라 시스템 API를 보므로, `HOME`을 바꾸는
방식으로는 홈을 옮길 수 없다. 그래서 이 변수를 둔다.

## 구조

```
core/       상태, 규칙, 세션 목록, 전달, 연동, Claude API 호출
cli/        hitai 명령
hook/       세션 쪽에서 실행되는 hitai-hook
src-tauri/  데스크톱 앱 백엔드
src/        앱 화면 (HTML/CSS/JS)
```

```bash
cargo test --workspace
```

## 알려진 한계

- 때린 걸 세션이 아는 시점은 그 세션이 다음 프롬프트를 받거나 도구를 호출할 때다.
  Codex는 즉시 큐에 들어가지만, 완전히 멈춰 있는 세션은 때려도 당장 반응하지 않는다.
- 누적 규칙은 세션을 가리지 않고 전체에 적용된다. 세션을 골라 겨냥하는 것은
  "방금 때린 것"과 "도구 호출 차단"이다.
